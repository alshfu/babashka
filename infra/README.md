# infra/

Сигналинг + TURN. Подробности эксплуатации — [`docs/server.md`](../docs/server.md).

## Запуск

```bash
cp .env.example .env
$EDITOR .env                     # TURN_SECRET и TURN_EXTERNAL_IP заполнить обязательно
docker compose up -d
curl -s localhost:8080/healthz
```

## Порты

| Порт | Кто | Зачем |
|---|---|---|
| 8080/tcp | signaling | WS + панель; наружу — только через TLS-прокси (`wss://`) |
| 3478/udp+tcp | coturn | STUN/TURN |
| 5349/tcp | coturn | TURN over TLS |
| 49152–65535/udp | coturn | relay-диапазон |

## Перед выкладкой наружу

- [ ] TLS-прокси перед сигналингом; клиенты ходят только по `wss://`.
- [ ] `TURN_SECRET` — случайный, не из примера, и не совпадает ни с чем другим.
- [ ] `TURN_EXTERNAL_IP` — реальный внешний адрес, иначе TURN бесполезен.
- [ ] `denied-peer-ip` действует (проверить: TURN не должен пускать во внутреннюю сеть —
      иначе это открытый прокси в вашу инфраструктуру).
- [ ] Журнал на постоянном томе, ротация 90 дней.
- [ ] `/metrics` закрыт от внешнего мира или вынесен на отдельный порт.
- [ ] В логах нет SDP, ICE-кандидатов и `note` (проверить `docker compose logs signaling`).

## Что делать при компрометации сервера

Ротировать `TURN_SECRET`, перевыпустить TLS, разобрать логи. **Переспаривание устройств
не требуется**: секреты пар живут только на телефонах, сервер их не знает и никогда не знал.
