# Сигналинг-сервер и инфраструктура

Сервер сознательно «глупый»: он сводит два устройства, раздаёт TURN-креды и пишет журнал
метаданных. Ни секретов пары, ни содержимого экрана у него нет — компрометация сервера
не даёт доступ к бабушкиному экрану ([security.md](security.md) §3).

Код: `server/`. Node.js ≥ 20, зависимость одна — `ws`.

---

## 1. Что делает

| Задача | Детали |
|---|---|
| Комнаты по `pairId` | максимум два сокета: роли `grandma` и `helper` |
| Присутствие | появление/пропадание сокета → `peer-state` второй стороне |
| Маршрутизация | `help-request`, `consent-*`, `offer`, `answer`, `ice`, `session-end` — по ролям, с проверкой направления |
| Сессии | выдача `sessionId`, таймауты (90 с на согласие, 10 мин без активности) |
| Лимиты | 5 `help-request`/час на пару, 3 подряд без ответа, 60 сообщений/10 с на сокет |
| TURN-креды | эфемерные, по схеме coturn REST |
| Журнал | только метаданные, JSONL или Postgres, доступ по `journalToken` |
| Пробуждение | FCM high-priority для роли `grandma` при `help-request` |

Чего сервер не делает: не хранит `pairSecret`, не разбирает SDP (кроме длины), не логирует
содержимое сообщений, не видит datachannel.

## 2. Конфигурация (env)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PORT` | `8080` | HTTP/WS |
| `TURN_HOST` | — | адрес coturn; без него отдаются только STUN |
| `TURN_SECRET` | — | общий статический секрет с coturn (`use-auth-secret`) |
| `TURN_TTL` | `43200` | срок жизни кредов, сек |
| `STUN_URLS` | `stun:stun.l.google.com:19302` | список через запятую |
| `JOURNAL_PATH` | `./data/journal.jsonl` | файл журнала |
| `JOURNAL_RETENTION_DAYS` | `90` | ротация |
| `FCM_KEY` | — | ключ для пробуждения; пусто → push отключён |
| `SERVE_PANEL` | `1` | раздавать ли `web/public` на `/panel/` |
| `MAX_MESSAGE_BYTES` | `65536` | лимит размера сообщения |

## 3. HTTP-эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/healthz` | `{"ok":true,"uptime":…,"pairs":…,"sessions":…}` |
| `GET` | `/api/ice` | ICE-конфиг (то же, что в `hello-ok`) — для отладки |
| `GET` | `/api/journal?pairId=…` | журнал пары, заголовок `X-Journal-Token` |
| `GET` | `/panel/*` | статика веб-панели |
| `WS` | `/ws` | сигналинг |

Метрики: `/metrics` в формате Prometheus (кол-во пар онлайн, сессий, отказов,
`auth-failed` — последнее должно быть около нуля; всплеск = атака или баг).

## 4. TURN (coturn)

```
# infra/coturn/turnserver.conf
listening-port=3478
tls-listening-port=5349
fingerprint
use-auth-secret
static-auth-secret=<TURN_SECRET>
realm=pult.local
no-multicast-peers
no-cli
denied-peer-ip=10.0.0.0-10.255.255.255       # запрет доступа во внутреннюю сеть
denied-peer-ip=192.168.0.0-192.168.255.255
denied-peer-ip=172.16.0.0-172.31.255.255
```

Креды эфемерные: `username = "<expiry>:<pairId>"`,
`credential = base64(HMAC-SHA1(static-auth-secret, username))`. Живут 12 часов,
привязаны к паре — украденные креды нельзя использовать вечно.

`denied-peer-ip` обязателен: без него TURN становится открытым прокси во внутреннюю сеть.

## 5. Развёртывание

```bash
cd infra && docker compose up -d      # signaling + coturn
```

- TLS: терминируется на nginx/Caddy перед сигналингом (`wss://`), coturn — со своим сертификатом.
- coturn нельзя ставить за NAT без `external-ip` — иначе кандидаты будут нерабочими.
- Порты: 443 (wss), 3478/udp+tcp, 5349/tcp, 49152–65535/udp (relay-диапазон).
- Масштабирование: состояние комнат в памяти → горизонтально масштабируется только
  с липкой сессией по `pairId` или общим Redis. Для пилота (10 семей) достаточно одного инстанса.

## 6. Эксплуатация

**Логи**: `{ts, level, pairId, role, type, sessionId}` — тип сообщения, но не содержимое.
SDP, ICE-кандидаты и `note` в логи не попадают. Хранение 14 дней.

**Что мониторить:**

| Сигнал | Значит |
|---|---|
| рост `auth-failed` | попытки подключиться чужим устройством или баг в MAC |
| рост `no-answer` у конкретной пары | бабушка не понимает запрос, либо помощник назойлив |
| рост доли TURN-сессий | проблемы с NAT/сетью, растёт трафик |
| пара офлайн > 6 ч | скорее всего сервис убит вендорной оптимизацией — уведомить помощника |
| `peer-lost` в середине сессий | нестабильная мобильная сеть |

**Инциденты**: компрометация сервера → ротация `TURN_SECRET`, перевыпуск TLS, разбор логов.
Секреты пар при этом **не** затронуты — переспаривание не требуется.

## 7. Приватность серверных данных

Хранится: `pairId`, `deviceId`, времена подключений, метаданные сессий, push-токены,
SHA-256 от `journalToken`. Всё остальное — нет.

Удаление по запросу семьи: `DELETE /api/journal?pairId=…` с `X-Journal-Token` стирает
журнал пары целиком.

## 8. Чек-лист приёмки

- [ ] `help-request` от роли `grandma` не маршрутизируется.
- [ ] `consent-granted` от роли `helper` не маршрутизируется.
- [ ] Второй сокет той же роли вытесняет первый (`replaced`), «призраков» не остаётся.
- [ ] Сообщение > 64 КБ → `bad-message`, сокет не падает.
- [ ] Превышение лимита `help-request` → `too-many-requests`, бабушке ничего не показано.
- [ ] Журнал недоступен без `X-Journal-Token` и с чужим токеном.
- [ ] В логах нет ни SDP, ни ICE-кандидатов, ни `pairSecret`.
- [ ] Перезапуск сервера: клиенты переподключаются сами, присутствие восстанавливается ≤ 5 с.
