# Этапы и границы

Соответствует п.5, п.9 и п.11 ТЗ. Правило: **V2 не начинается, пока V1 не проверен
на реальных семьях.** Управление устройством — самая заманчивая функция и самая опасная
для сроков и для прохождения в стор; она сознательно отложена.

## Этап 1. Прототип

Цель: доказать, что сценарий 1-2-3 работает.

- [x] Протокол сигналинга и взаимной аутентификации ([protocol.md](protocol.md))
- [x] Сигналинг-сервер: комнаты, присутствие, маршрутизация, лимиты, журнал, TURN-креды
- [x] Общие тест-векторы пары; Node, Web Crypto и Kotlin дают одинаковый MAC
- [x] Веб-панель помощника + отладочная вкладка «бабушки» (`getDisplayMedia`)
- [x] Android: каркас Gradle, общий модуль `core`, клиент сигналинга, машина состояний
- [x] Android: скелеты обоих приложений собираются в APK
- [x] Android: транспорт WebRTC поверх libwebrtc — захват `MediaProjection` → поток,
      приём на стороне помощника, канал `pult-control`, гашение экрана
- [x] Android: overlay — рамка, подпись, указатель, «Стоп»
- [ ] Полный проход 1-2-3 в браузере с проверкой MAC (нужен ручной прогон в двух вкладках)
- [ ] Прогон Android ↔ Android и Android ↔ браузер на живых устройствах
- [ ] Android: спаривание NFC (HCE) и сканер QR
- [ ] Android: чтение серверного журнала по `journalToken` в приложении помощника

Критерий: между двумя браузерами и между двумя телефонами поднимается сессия, экран виден,
указатель попадает в точку, «Стоп» работает.

Критерий готовности V1 (п.12 ТЗ + добавленное):

1. Внук инициирует помощь, бабушка одним нажатием «Разрешить» — и внук за минуту видит
   её экран и ведёт по нему указателем.
2. Чужое устройство подключиться не может (проверка ключа).
3. Мошеннический звонок не проходит (белый список).
4. Каждая сессия — включая отклонённые и оставшиеся без ответа — видна бабушке и записана
   в журнал.
5. Сервис переживает сутки в фоне на MIUI/Huawei или честно сигналит внуку, что он мёртв.
6. Пара восстанавливается после смены телефона помощника.

## Этап 3. Пилот

10 реальных семей, 6–8 недель. Замеряем:

| Метрика | Зачем |
|---|---|
| Частота запросов помощи | понять реальный ритм: раз в день или раз в месяц |
| Доля «Разрешить» / «Не сейчас» / без ответа | понятен ли запрос; не назойлив ли помощник |
| Время от запроса до показа экрана | целевое: < 60 с |
| Доля сессий через TURN | сколько стоит трафик |
| Смертность сервиса в фоне по вендорам | где продукт не работает |
| Сколько звонков заблокировано и сколько из них ложно | не отрезали ли поликлинику |
| Чего не хватило (со слов семей) | вход в V2 |

Пилот заканчивается решением: что из V2 делать первым — а не заранее составленным списком.

## Этап 4. V2

| Функция | Условие запуска |
|---|---|
| Управление устройством (нажатия за бабушку) | отдельный модуль; декларация AccessibilityService в Google Play, готовность к отказу; см. ниже |

| Второй (резервный) помощник | добавление только с устройства из пары, при личной встрече |
| Голосовое сопровождение для бабушки | по итогам пилота |

### Про управление устройством

Ограничение платформы, а не наше нежелание: полный контроль на Android требует
`AccessibilityService`, который проходит ручную проверку Google, часто отклоняется
для «удалённой помощи» и отключается в защищённом режиме Android 17.

Поэтому:
- V1 — только просмотр + указатель, никакого Accessibility (проходит легко);
- V2 — управление как **отдельный модуль**, включаемый бабушкой на сессию, с журналом,
  с автоматическим отключением на банковских приложениях;
- альтернатива на настроенных телефонах — режим Device Owner, без Accessibility.

Если Google откажет в декларации — V1 остаётся полноценным продуктом. Это и есть причина
такой нарезки этапов.

## Границы — чего не делаем никогда

- Скрытый режим слежки. Ни по чьей просьбе, ни под каким флагом
  ([security.md](security.md) §2).
- Обход блокировок, VPN-для-цензуры. Здесь «туннель» = связь двух своих устройств.
- Постоянный молчаливый доступ ко всему.
- Сбор SMS, истории звонков, контактов, геолокации на сервер.
- Хранение содержимого экрана где бы то ни было.
- Удалённое спаривание в любом виде — включая «ссылку для восстановления».
- Опция «разрешать всегда» в окне согласия.

## Дистрибуция

- Google Play — основной канал; требования и декларации: [store-compliance.md](store-compliance.md).
- Верификация разработчика Google обязательна с сентября 2026 и для установки вне Play —
  проходить заранее, не в последний момент.
- APK вне Play — только как запасной путь для пилота, с подписанной сборкой и понятной
  инструкцией.
