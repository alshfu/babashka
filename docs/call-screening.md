# Белый список звонков

Ключевая функция безопасности из ТЗ, п.7. Прямо закрывает главный сценарий атаки на
пожилого человека: звонок «от внука» или «из банка» с последующим давлением.

Реализация: `CallScreeningService` — штатный API Android, **не** требующий
AccessibilityService и не читающий историю звонков.

---

## 1. Как работает

```
входящий звонок
      │
      ▼
CallScreeningService.onScreenCall(details)
      │
      ├─ номер в белом списке ────────────► пропустить, обычный звонок
      │
      ├─ номер отсутствует/скрыт ─────────► отклонить + запись в журнал
      │
      └─ номер не в списке ───────────────► по настройке:
                                             «блокировать» (по умолчанию)
                                             «пропускать с меткой „возможно мошенник“»
```

Решение принимается **локально**, за миллисекунды, без обращения к сети: номер сверяется
с локальной базой. Никакие номера на сервер не отправляются.

## 2. Что в белом списке

- номера семьи, внесённые при настройке;
- номер помощника (обязательно, автоматически при спаривании);
- номера, добавленные бабушкой вручную с главного экрана («Этот номер — свой»);
- в V2 — список, который ведёт помощник со своего телефона (синхронизация через datachannel
  во время сессии, **не** через сервер).

Нормализация: E.164, сравнение по последним 10 цифрам, чтобы `+7`, `8` и запись без кода
считались одним номером. Короткие номера (112, 103, 101, 102, 104) — **всегда** в списке
и неудаляемы: экстренные службы блокировать нельзя ни при каких настройках.

## 3. Режимы

| Режим | Поведение | Кому |
|---|---|---|
| Строгий (по умолчанию) | всё, чего нет в списке, отклоняется молча | если бабушке звонят только свои |
| Мягкий | звонок проходит, но помечен «возможно мошенник» крупной плашкой | если ждут звонков из поликлиники, курьеров |
| Выключен | фильтр не работает, но приложение остаётся | по явному решению семьи |

Режим переключается на телефоне бабушки и виден в приложении помощника. Тихо изменить
его помощник не может.

## 4. Что бабушка видит

- Заблокированный звонок → уведомление в шторке: «Заблокирован звонок с номера +7…,
  нажмите, если это свой». Одно нажатие добавляет номер в белый список.
- Список заблокированных за неделю — на главном экране, крупным шрифтом.
- Внук видит тот же список в журнале: если бабушке названивают, семья узнает об этом.

Молчаливой блокировки без следа не бывает: пропущенный важный звонок должен быть заметен
и исправим одним нажатием.

## 5. Технические требования

- `<service android:permission="android.permission.BIND_SCREENING_SERVICE">` +
  `intent-filter` на `CallScreeningService`.
- Роль `ROLE_CALL_SCREENING` запрашивается через `RoleManager` при настройке; без неё
  функция не работает, и приложение честно об этом сообщает.
- Только одно приложение в системе может быть screening-приложением. Если роль занята
  (частая ситуация: Яндекс.Определитель, антиспам оператора) — показываем понятное объяснение
  и предлагаем выбрать, не ломая существующее молча.
- Ответ должен уложиться в отведённое системой время (единицы секунд) — никаких сетевых
  запросов в `onScreenCall`.
- `CallResponse.Builder().setDisallowCall(true).setRejectCall(true).setSkipCallLog(false)` —
  журнал системы **не** подменяем: бабушка должна видеть, что звонок был.

## 6. Чего не делаем

- Не загружаем номера на сервер и не строим «облачную базу мошенников».
- Не читаем историю звонков (`READ_CALL_LOG` не запрашивается).
- Не записываем разговоры.
- Не блокируем экстренные номера.
- Не показываем «определение номера» из внешних баз — это чужой продукт и чужие данные.

## 7. Чек-лист приёмки

- [ ] Звонок с номера помощника проходит всегда.
- [ ] Звонок с неизвестного номера в строгом режиме не проходит и попадает в уведомление.
- [ ] Экстренный номер проходит в любом режиме, удалить его из списка невозможно.
- [ ] Добавление номера из уведомления — одно нажатие.
- [ ] Роль занята другим приложением → понятное объяснение, а не молчаливый отказ.
- [ ] Ни один номер не уходит в сеть (проверка перехватом трафика).
