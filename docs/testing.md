# План тестирования и приёмка

Три уровня: автотесты (быстро, на каждый коммит), стенд (браузер + эмулятор, на каждый PR),
живые устройства (перед релизом). Отдельно — чек-лист приёмки V1, который проходится
целиком и вручную.

---

## 1. Автотесты

### Сервер (`server/`, `node --test`)

| Что проверяем | Почему это важно |
|---|---|
| `hello` → комната, присутствие, `hello-ok` с ICE | базовый путь |
| сообщение до `hello` → `not-authenticated` + разрыв | нельзя слать что-то анонимно |
| `help-request` от роли `grandma` не маршрутизируется | инициировать может только помощник |
| `consent-granted` от роли `helper` не маршрутизируется | согласие даёт только бабушка |
| второй сокет той же роли вытесняет первый (`replaced`) | смена сети не оставляет «призраков» |
| таймаут согласия 90 с → `no-answer` обеим сторонам | зависший запрос не живёт вечно |
| лимит 5 `help-request`/час → `too-many-requests` | защита от назойливости |
| 60 сообщений/10 с → `rate-limited` | защита от флуда |
| сообщение > 64 КБ → `bad-message`, сокет жив | устойчивость |
| чужой/протухший `sessionId` → `unknown-session` | нет перекрёстных сессий |
| журнал: запись `declined`, `no-answer`, `auth-failed` | прозрачность не выборочная |
| журнал недоступен без/с чужим `X-Journal-Token` | доступ только у пары |
| в логах нет SDP, ICE, `note`, секретов | приватность в эксплуатации |

### Крипто (общий для `core` и `web`)

| Тест | Ожидание |
|---|---|
| векторы MAC совпадают между Kotlin, Node и Web Crypto | иначе клиенты не договорятся |
| подмена любого поля транскрипта (`sessionId`, nonce, любой fp) | MAC не сходится |
| нормализация отпечатка DTLS: регистр, разделители | одинаковый результат на всех платформах |
| сравнение MAC константное по времени | нет утечки по таймингу |
| nonce: 16 байт CSPRNG, без повторов в 10⁶ генераций | нет реплея |

Общие тест-векторы лежат в `protocol/test-vectors.json` и прогоняются **всеми тремя**
реализациями. Расхождение = сломанная совместимость.

### Android (`core`, unit)

- машина состояний `ГОТОВ → ЗАПРОС → СЕССИЯ` — недопустимые переходы бросают;
- клиент сигналинга: переподключение с backoff, дедупликация сообщений;
- `PairStore`: секрет не сериализуется в `toString()`, не попадает в логи;
- нормализация номеров для белого списка (`+7`, `8`, без кода → одно и то же);
- список экстренных номеров неудаляем.

## 2. Стенд (без живых телефонов)

`web/public/?role=grandma` + `?role=helper` в двух вкладках — полный сценарий 1-2-3
с настоящей проверкой MAC и настоящим WebRTC (экран отдаётся через `getDisplayMedia`).

Сценарии стенда:

1. Счастливый путь: запрос → «Разрешить» → экран → указатель → «Стоп».
2. Отказ: «Не сейчас» → сессии нет, запись в журнале есть.
3. Молчание: 90 с → `no-answer` у обеих сторон.
4. Злой сервер: подменить `a=fingerprint` в ретранслируемом SDP (флаг `--evil` у сервера) →
   **сессия не поднимается**, обе стороны получают `auth-failed`.
5. Чужой помощник: подключиться с верным `pairId`, но неверным `pairSecret` → `auth-failed`,
   экран не передаётся ни кадра.
6. Обрыв: убить сокет посреди сессии → переподключение, `peer-lost` в журнале.
7. Флуд: 10 запросов подряд → лимит сработал, бабушке показан максимум один запрос.

Сценарии 4 и 5 — главные. Если они проходят «успешно» (сессия поднялась), релиза нет.

## 3. Живые устройства

Минимальная матрица (то, что реально у пожилых людей):

| Устройство | Android | Зачем |
|---|---|---|
| Xiaomi Redmi (MIUI) | 12–14 | худший случай по убийству фона |
| Huawei без GMS | 10–12 | нет FCM — проверить деградацию |
| Samsung A-серия | 13–14 | самый частый массовый телефон |
| дешёвый без NFC | 8–9 (minSdk 26) | QR-путь спаривания обязателен |
| Pixel | 15–16 | эталон поведения платформы |

Проверки на устройствах:

- сутки в фоне без сессий: сервис жив, батарея < 3 %, уведомление на месте;
- перезагрузка → автозапуск;
- запрос помощи при выключенном экране → будит, показывает поверх экрана блокировки;
- мобильная сеть (не Wi-Fi), переход 4G → Wi-Fi посреди сессии → переподключение;
- симметричный NAT (мобильный оператор) → TURN подхватывается;
- банковское приложение на переднем плане → гашение ≤ 500 мс;
- звонок с неизвестного номера → заблокирован, уведомление показано;
- звонок 112 → проходит.

## 4. Тестирование с людьми

Пять пожилых пользователей, никогда не видевших приложение. Без подсказок наблюдаем:

- понимает ли она, что означает окно «Петя хочет помочь»;
- находит ли кнопку «Разрешить» за ≤ 5 с;
- понимает ли, что во время сессии её видят (спрашиваем прямо: «сейчас кто-то видит ваш экран?»);
- находит ли «Стоп» без подсказки;
- пугает ли постоянное уведомление.

Провал последнего пункта — не косметика: если бабушка не понимает, что её видят,
нарушено правило прозрачности ([security.md](security.md) §2), и это блокер.

## 5. Безопасностные проверки перед релизом

- [ ] Перехват трафика (mitmproxy + charles на устройстве): `pairSecret` не встречается нигде.
- [ ] `adb backup` / облачный бэкап: файла ключей нет.
- [ ] `logcat` во время полной сессии: ни секрета, ни SDP, ни кадров.
- [ ] Статический анализ на утечки (`detekt`, `lint`), проверка `allowBackup=false`.
- [ ] Попытка запустить захват экрана в обход `SessionController` — невозможна по коду
      (единственная точка входа, проверяется code review).
- [ ] Проверка, что нет ни одной настройки, скрывающей уведомление или рамку.
- [ ] TURN не работает как открытый прокси (`denied-peer-ip` действует).
- [ ] Внешний аудит крипто-части перед публичным релизом.

## 6. Чек-лист приёмки V1

Проходится целиком, вручную, на живых устройствах. Любой невыполненный пункт = нет релиза.

1. [ ] Внук нажал «Помочь», бабушка нажала «Разрешить» — экран виден за < 60 с.
2. [ ] Указатель попадает в ту же точку (±2 % размера экрана).
3. [ ] Чужое устройство с верным `pairId` подключиться не может.
4. [ ] Подмена SDP на сервере не даёт сессии.
5. [ ] «Не сейчас», молчание, «Стоп» — работают и записаны в журнал.
6. [ ] Рамка, подпись и уведомление видны всю сессию и не отключаются.
7. [ ] Мошеннический звонок не проходит; 112 проходит.
8. [ ] Сутки в фоне на MIUI: сервис жив либо внук предупреждён.
9. [ ] Пара восстанавливается после смены телефона внука (повторная встреча).
10. [ ] Журнал виден обеим сторонам и содержит все запросы, включая отклонённые.
11. [ ] Пять пожилых пользователей прошли сценарий без подсказок.
