# Архитектура

## 1. Общая картина

```
   ┌───────────────────────┐                    ┌───────────────────────┐
   │  Телефон бабушки      │                    │  Телефон/браузер внука│
   │  ─────────────────    │                    │  ──────────────────── │
   │  foreground service   │                    │  панель присутствия   │
   │  запрос «Разрешить»   │                    │  кнопка «Помочь»      │
   │  MediaProjection      │                    │  просмотр экрана      │
   │  overlay-указатель    │                    │  указатель            │
   │  EncryptedSharedPrefs │                    │  Keystore / IndexedDB │
   └───────┬───────────────┘                    └──────────────┬────────┘
           │                                                   │
           │  WS: hello / help-request / consent / offer / ice │
           └──────────────┐                    ┌───────────────┘
                          ▼                    ▼
                   ┌──────────────────────────────────┐
                   │  Сигналинг (Node.js + ws)        │   знает: pairId, кто в сети,
                   │  журнал метаданных, TURN-креды   │   метаданные сессий
                   │  НЕ знает: pairSecret, контент   │
                   └──────────────────────────────────┘
                          │  (только при плохой сети)
                          ▼
                   ┌──────────────────────────────────┐
                   │  coturn (TURN/STUN)              │   ретранслирует байты,
                   │                                  │   расшифровать не может
                   └──────────────────────────────────┘

           ╔═══════════════════════════════════════════════════╗
   бабушка ║  WebRTC: DTLS-SRTP видео экрана + datachannel     ║ внук
           ║  end-to-end, ключи только на устройствах          ║
           ╚═══════════════════════════════════════════════════╝
```

Сервер — «телефонная барышня»: соединяет и уходит. Через него не проходит ни одного
кадра экрана и ни одного ключа.

## 2. Компоненты

### Приложение бабушки (`android/grandma`)
Живёт как foreground service с постоянным уведомлением. Бабушка его **не открывает** —
но всегда видит. Отвечает за:
- присутствие (держит сокет к сигналингу, переподключается сам);
- показ входящего запроса «Петя хочет помочь» поверх всего — одна большая кнопка
  «Разрешить» и вторая, поменьше, «Не сейчас»;
- проверку подлинности помощника (HMAC по секрету пары) **до** запуска захвата;
- захват экрана (MediaProjection) и передачу его по WebRTC;
- overlay: рамка «Петя помогает вам», указатель, кнопка «Стоп»;
- гашение экрана при банковских приложениях;
- фильтр звонков (CallScreeningService);
- локальный журнал сессий.

### Приложение внука (`android/helper`) и веб-панель (`web/`)
- видит состояние: «бабушка в сети / не в сети»;
- кнопка «Помочь бабушке» — отправляет запрос и ждёт её согласия;
- после «Разрешить» поднимает WebRTC и показывает экран;
- рисует указатель пальцем/мышью → координаты уходят бабушке;
- ведёт список доверенных номеров (V2), смотрит журнал сессий.

Веб-панель — не «урезанная версия», а полноценный второй клиент: она же служит
отладочным стендом и позволяет проверять протокол без двух телефонов.

### Общий модуль (`android/core`)
Единственное место, где живут: типы сообщений протокола, вычисление MAC, генерация
nonce, разбор SDP-отпечатков, клиент сигналинга с переподключением. Дублировать эту
логику в двух приложениях нельзя — разъедется.

### Сигналинг (`server/`)
Node.js + `ws`. Держит комнаты по `pairId`, ретранслирует сообщения между двумя
ролями, раздаёт TURN-креды, пишет журнал метаданных, будит внука через FCM.
Состояние — в памяти + журнал в файл/БД; сервер сознательно «глупый» и заменяемый.

### coturn (`infra/`)
Нужен, когда прямое соединение не поднимается (симметричный NAT, мобильный оператор).
Ретранслирует зашифрованный поток, содержимого не видит.

## 3. Поток управления: от кнопки до экрана

| # | Кто | Что происходит |
|---|---|---|
| 1 | внук | нажал «Помочь бабушке» → `help-request` |
| 2 | сервер | проверяет лимит запросов, выдаёт `sessionId`, шлёт запрос бабушке; если её телефон спит — FCM high-priority будит приложение |
| 3 | бабушка | поверх всего всплывает «Петя хочет помочь» → **«Разрешить»** → `consent-granted` (либо «Не сейчас» → `consent-denied`, либо 90 с молчания → `no-answer`) |
| 4 | внук | создаёт offer, шлёт `offer` + `nonceH` |
| 5 | бабушка | отвечает `answer` + `nonceG` + `macG` (HMAC по секрету пары и **обоим** DTLS-отпечаткам) |
| 6 | внук | проверяет `macG`, шлёт `auth-confirm` + `macH` |
| 7 | бабушка | проверяет `macH` — **и только теперь** запускает MediaProjection |
| 8 | оба | ICE, DTLS, поток экрана + datachannel `pult-control` |
| 9 | бабушка | на экране рамка и подпись «Петя помогает вам», в шторке — «идёт показ» |
| 10 | любой | «Стоп» → `stop` в datachannel + `session-end` на сервер → запись в журнал |

Два принципиальных шага:

- **шаг 3** — единственный вход в сессию. Запрос помощника сам по себе не даёт ничего:
  без нажатия «Разрешить» приложение бабушки не отвечает на `offer` вообще.
- **шаг 7** — захват экрана не стартует, пока личность помощника не подтверждена
  локально, на устройстве бабушки. См. [protocol.md](protocol.md) §4.

Инициатива у внука снимает с бабушки задачу «догадаться позвать», но переносит на неё
роль привратника. Отсюда — лимиты на частоту запросов и тихие часы ([protocol.md](protocol.md) §3):
без них помощь легко превращается в назойливость.

## 4. Границы доверия

| Кому доверяем | В чём |
|---|---|
| Устройству бабушки | во всём: оно решает, пускать ли, что показывать, когда гасить |
| Устройству внука | только после проверки MAC, и только на текущую сессию |
| Сигналинг-серверу | в маршрутизации и присутствии. **Не** в подлинности сторон и **не** в конфиденциальности |
| TURN-серверу | в доставке байтов. Содержимое ему недоступно |

Из этого следует: компрометация сервера **не** даёт доступ к экрану бабушки.
Максимум — отказ в обслуживании и метаданные (кто, когда, сколько длилась сессия).

## 5. Состояния устройства бабушки

```
      ┌──────────┐  сеть есть        ┌──────────┐  запрос от внука  ┌──────────┐
      │ ОФЛАЙН   │ ────────────────► │ ГОТОВ    │ ────────────────► │ ЗАПРОС   │
      └──────────┘ ◄──────────────── └──────────┘ ◄──────────────── └──────────┘
                     сеть пропала         ▲   «Не сейчас» / 90 с молчания │
                                          │                              │ «Разрешить»
                                          │                              │  + auth OK
                                          │        «Стоп» / обрыв        ▼
                                          └───────────────────────  ┌──────────┐
                                                                    │ СЕССИЯ   │
                                                                    └──────────┘
```

- В состоянии `ГОТОВ` не передаётся ничего, кроме keepalive.
- В состоянии `ЗАПРОС` экран ещё не захватывается: показывается только окно с вопросом.
  Отказ и молчание равнозначны — сессии не будет.
- Из `СЕССИЯ` выход всегда доступен одним действием — кнопка «Стоп» поверх всего.
- Любой переход в `СЕССИЯ` и из неё пишется в локальный журнал и в серверный.

## 6. Технологический стек

| Слой | Технология | Почему |
|---|---|---|
| Приложения | Android, Kotlin, minSdk 26 | покрывает телефоны, которые реально у пожилых |
| Соединение | WebRTC (DTLS-SRTP), сборка `io.getstream:stream-webrtc-android` | e2e-шифрование из коробки, NAT traversal, зрелый стек; пакеты `org.webrtc` — сборку можно заменить без правок кода |
| Сигналинг | Node.js + `ws` | простой, легко держать «глупым» и заменяемым |
| Ретранслятор | coturn | стандарт индустрии, ставится в docker |
| Захват экрана | MediaProjection + foreground service | единственный легальный путь на Android без root |
| Указатель | WindowManager overlay (`TYPE_APPLICATION_OVERLAY`) | рисует поверх любого приложения, не требует Accessibility |
| Секрет пары | EncryptedSharedPreferences (Android Keystore) | ключ не извлекается из устройства |
| Пробуждение | FCM high-priority | доставляет вызов, когда приложение усыплено системой |
| Белый список | CallScreeningService | штатный API, не требует Accessibility |

## 7. Что осознанно не делается

- Управление устройством (нажатия за бабушку) — **не в V1**: требует AccessibilityService,
  ручной проверки Google и ломается в защищённом режиме Android 17. Отдельный модуль V2,
  см. [roadmap.md](roadmap.md).
- Никакого VPN и обхода блокировок. «Туннель» здесь — связь двух своих устройств.
- Никакого хранения кадров экрана, SMS, истории звонков на сервере.
