# Политика безопасности и приватности

Этот документ — не формальность. На нём держится и легальность продукта, и доверие семьи.
Изменения сюда вносятся только осознанным решением команды, с записью в [decisions.md](decisions.md).

---

## 1. Девять правил (из ТЗ, п.8)

| # | Правило | Как обеспечено технически |
|---|---|---|
| 1 | **Согласие первично** | Запрос помощника — это только вопрос. Сессия стартует по нажатию «Разрешить» на телефоне бабушки; захват экрана включается локальным действием, а не сетевым сообщением. `consent-granted` от роли `helper` сервер не маршрутизирует. Опции «разрешать всегда» не существует |
| 2 | **Доступ временный** | Доступ живёт в пределах `sessionId`. Нет постоянного разрешения, нет «запомнить помощника навсегда» |
| 3 | **Пара закрыта** | Подключается только устройство, знающее `pairSecret`. Проверка HMAC локально на телефоне бабушки |
| 4 | **Прозрачность** | Рамка + подпись во время сессии, постоянное уведомление, локальный и серверный журнал |
| 5 | **Минимум данных** | На сервер уходят только метаданные сессий. Ни кадров, ни SMS, ни истории звонков |
| 6 | **Банки под защитой** | Устройство бабушки само гасит поток при банковском приложении на переднем плане |
| 7 | **Шифрование** | WebRTC DTLS-SRTP end-to-end; секрет пары — в EncryptedSharedPreferences, на сервер не попадает |
| 8 | **Право отключить** | Кнопка «Стоп» поверх всех окон, всегда доступна, одно нажатие |
| 9 | **Видимый фон, не stalkerware** | Постоянное уведомление, обычная иконка и имя, рамка при подключении. Скрытого режима не существует |

## 2. Правило видимости — почему оно не обсуждается

Скрытый фоновый режим не реализуется **никогда, ни по чьей просьбе**, включая просьбы
«так бабушке будет проще» и «мы же родственники».

- Невидимый сервис с доступом к чужому экрану — это ровно определение stalkerware.
  Google Play (Developer Program Policy, раздел про Stalkerware) снимает такие приложения
  и банит аккаунт разработчика; Apple — аналогично.
- Партнёры и антивирусы помечают такое как угрозу, установка блокируется.
- Правовой риск: доступ к устройству без осведомлённости владельца.

«Не усложнять бабушке жизнь» достигается тем, что она **не открывает приложение**,
а не тем, что она **не знает о подключении**. Это разные вещи.

Признаки видимости, которые нельзя убирать ни при каких настройках:

- постоянное уведомление «Пульт — помощь родных подключена» (канал без возможности отключения,
  `IMPORTANCE_LOW`, но не скрываемое приложением);
- рамка по краю экрана + подпись «<Имя> помогает вам» на всё время сессии;
- кнопка «Стоп» поверх всего;
- обычная иконка и обычное имя в списке приложений;
- запись каждой сессии в журнал, доступный всей семье.

Тест на нарушение: если существует комбинация настроек, при которой бабушка не может
понять, что к ней подключены, — это баг уровня блокера релиза.

## 3. Модель угроз

| Угроза | Кто | Защита |
|---|---|---|
| Мошенник звонит «под видом внука» | внешний | Белый список звонков ([call-screening.md](call-screening.md)); чужой номер не дозванивается |
| «Пришлите код из СМС / перейдите по ссылке» | внешний | Спаривание невозможно удалённо. Кода, который можно продиктовать, не существует |
| Подключение чужого устройства | внешний | HMAC-проверка пары локально на телефоне бабушки |
| MITM на сигналинге, подмена SDP | сервер / сеть | MAC считается по **обоим** DTLS-отпечаткам; сервер не знает секрета и подменить не может |
| Компрометация сервера | инфраструктура | Сервер не хранит ни секретов, ни контента. Максимум — DoS и метаданные |
| Кража телефона внука | физическая | Секрет в Keystore/EncryptedSharedPreferences, экран-лок обязателен; отзыв пары с телефона бабушки |
| Кража телефона бабушки | физическая | Тот же Keystore; помощник видит разрыв пары; повторное спаривание — только вблизи |
| Помощник злоупотребляет доступом | доверенное лицо | Доступ только на сессию и только по нажатию «Разрешить»; журнал виден всей семье; банковские приложения гасятся |
| Помощник дёргает бабушку запросами | доверенное лицо | Лимит 5 запросов в час и 3 подряд без ответа, тихие часы 22:00–08:00, все запросы (включая отклонённые) в журнале |
| Подделка согласия сервером | сервер | `consent-granted` ничего не открывает: поток отдаёт устройство бабушки после локального нажатия, и только после проверки MAC |
| Давление «нажмите Разрешить» по телефону | социальная инженерия | Чужой номер не дозванивается (белый список); в окне запроса — только имя из пары, подменить его нельзя |
| Реплей старой сессии | сеть | Одноразовые nonce, `sessionId` не переиспользуется, MAC привязан к транскрипту |
| Слежка через присутствие | сервер | Присутствие — единственная фоновая утечка; журнал метаданных ротируется (90 дней) |

## 4. Обращение с ключами

- `pairSecret` (32 байта, CSPRNG) создаётся на телефоне бабушки при спаривании.
- Хранение: Android — `EncryptedSharedPreferences` поверх Android Keystore
  (`MasterKey` c `AES256_GCM`, `setUserAuthenticationRequired(false)` — иначе сервис не поднимется
  до разблокировки, а бабушке нужен рабочий фон); iOS/веб — Keychain / non-extractable CryptoKey.
- Секрет **никогда** не сериализуется в логи, аналитику, бэкапы (`android:allowBackup="false"`,
  `dataExtractionRules` исключают файл ключей).
- Ротация: при каждом новом спаривании создаётся новый секрет; старый удаляется немедленно.
- Отзыв: «Забыть помощника» на телефоне бабушки стирает секрет — все попытки подключения
  тут же перестают проходить проверку.

## 5. Данные: что собираем и что нет

**Собираем (на сервере):**
- `pairId`, `deviceId`, время подключения/отключения — для присутствия;
- метаданные сессии: `sessionId`, `pairId`, инициатор, начало, конец, причина завершения,
  был ли показ экрана;
- push-токен FCM внука.

**Не собираем никогда:** кадры и записи экрана, аудио, SMS, историю звонков, содержимое
уведомлений, контакты, геолокацию, содержимое datachannel, `pairSecret`.

**Хранение:** журнал — 90 дней, потом удаление. Логи сервера — без содержимого сообщений
(только тип и `pairId`), 14 дней. Экран не пишется на диск нигде и никогда.

**Доступ к журналу:** по `journalToken`, выводимому из секрета пары. Сервер хранит только
SHA-256 токена, то есть сам журнал прочитать «изнутри» не может без участия устройства.

## 6. Инварианты, которые проверяются тестами

Каждый пункт — автотест или пункт чек-листа приёмки (см. [testing.md](testing.md)):

1. Захват экрана не запускается, если MAC помощника не проверен.
2. Без нажатия «Разрешить» экран не передаётся: `offer` без предшествующего согласия
   остаётся без ответа, `consent-granted` от роли `helper` не маршрутизируется.
3. Отказ («Не сейчас») и молчание 90 с дают один результат — сессии нет; повтор запроса
   упирается в лимит частоты.
4. Подмена `a=fingerprint` в SDP на сервере → сессия не поднимается.
5. Постоянное уведомление невозможно скрыть настройками приложения.
6. Кнопка «Стоп» завершает сессию менее чем за 1 с и снимает MediaProjection.
7. Открытие приложения из списка банковских → поток гаснет ≤ 500 мс.
8. Секрет пары не встречается ни в одном логе, бэкапе, сетевом пакете к серверу.
9. После «Забыть помощника» ни одна сессия не поднимается.
10. Журнал содержит все запросы и сессии, включая отклонённые (`declined`),
    оставшиеся без ответа (`no-answer`) и неуспешные (`auth-failed`).

## 7. Ответственное раскрытие

Уязвимости — на security@<домен>. Ответ в течение 5 рабочих дней, исправление критичных —
в течение 30 дней. Публичное раскрытие после выпуска исправления. Благодарности — в релиз-ноутс.

## 8. Границы (из ТЗ, п.9)

Не делаем: обход блокировок и VPN-для-цензуры; постоянный молчаливый доступ; сбор SMS
и истории звонков на сервер; скрытый режим слежки; хранение содержимого экрана.
