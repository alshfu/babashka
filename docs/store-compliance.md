# Требования сторов и юридическая рамка

Приложение удалённой помощи с доступом к экрану — категория повышенного внимания
у Google. Половина отказов здесь случается не из-за функций, а из-за неаккуратных
формулировок в описании и отсутствующих деклараций.

> Политики Play меняются; даты и названия разделов ниже проверять на актуальность
> перед каждой подачей. Здесь — устойчивая часть требований и наши ответы на них.

---

## 1. Главный риск: stalkerware

Google снимает и банит приложения, которые дают доступ к чужому устройству без ведома
владельца. Граница проходит по **осведомлённости пользователя устройства**, а не по
намерению («мы же родственники» не аргумент).

Наши ответы, встроенные в продукт, а не написанные в описании:

| Требование политики | Как выполнено |
|---|---|
| Пользователь знает о слежении | постоянное уведомление, обычная иконка и имя, рамка и подпись во время сессии |
| Нет скрытых иконок/имён | скрытый режим не реализуется никогда ([security.md](security.md) §2) |
| Согласие на каждый доступ | сессия только после нажатия «Разрешить»; опции «всегда» нет |
| Прекращение в любой момент | кнопка «Стоп» поверх всего, < 1 с |
| Прозрачность истории | журнал доступен всей семье, не редактируется |

В описании в сторе — прямо и первым абзацем: «Приложение всегда видно на телефоне
пожилого человека. Подключение возможно только после его подтверждения». Формулировок
вроде «незаметно», «скрытно», «контроль за родными» — не использовать нигде,
включая скриншоты и промо.

## 2. Декларации и формы Play Console

| Декларация | Что указываем |
|---|---|
| Data safety | собираем: идентификаторы устройства/пары, метаданные сессий, push-токен. Не собираем: сообщения, звонки, контакты, геолокацию, содержимое экрана. Данные шифруются при передаче, удаление по запросу |
| Foreground service types | `mediaProjection` (показ экрана по запросу) + `dataSync` (присутствие) с обоснованием и видео-демонстрацией |
| `SYSTEM_ALERT_WINDOW` | обоснование: рамка-индикатор, кнопка «Стоп», указатель |
| `PACKAGE_USAGE_STATS` | обоснование: автоматическое отключение показа на банковских приложениях (защитная функция) |
| Call screening / `RoleManager` | обоснование: белый список для защиты от мошенников; `READ_CALL_LOG` **не** запрашиваем |
| Sensitive permissions | ничего из списка «требует одобрения» в V1, кроме перечисленного |
| Accessibility | в V1 **не используется**. Это сознательно: снимает самую тяжёлую проверку |
| Целевая аудитория | взрослые; приложение не для детей |

К заявке приложить: короткое видео полного сценария (запрос → «Разрешить» → показ → «Стоп»),
скриншоты постоянного уведомления и рамки, ссылку на политику приватности.

## 3. V2: управление устройством

`AccessibilityService` для управления проходит ручную проверку, часто отклоняется для
«удалённой помощи» и отключается в защищённом режиме Android 17.

План:
- V2-модуль включается бабушкой на сессию, с журналом и с отключением на банковских приложениях;
- декларация подаётся отдельно, с видео и объяснением, почему без Accessibility нельзя;
- запасной путь — Device Owner на телефонах, настроенных «под ключ» (не требует Accessibility);
- при отказе Google V1 остаётся полноценным продуктом ([roadmap.md](roadmap.md)).

## 4. Дистрибуция вне Play

Верификация разработчика Google обязательна с сентября 2026 и для установки APK вне Play.
Проходить заранее: она требует документов и времени, и внезапно упереться в неё перед
пилотом — потерять недели.

Сборки для пилота: подписанные, с явным экраном «это тестовая версия», с тем же
постоянным уведомлением и той же моделью согласия. Тестовая сборка не имеет права
быть менее видимой, чем релизная.

## 5. Юридическое

- **Политика приватности** — обязательна, публичная ссылка, на русском. Содержание —
  разделы 5 и 7 [security.md](security.md), человеческим языком.
- **Пользовательское соглашение**: кто такой помощник, что он видит, что не видит,
  как отозвать доступ.
- **Персональные данные (152-ФЗ, если работаем в РФ)**: собираем минимум; определить
  оператора, основание обработки (согласие), сроки хранения (90 дней журнал), место
  хранения. Содержимое экрана не обрабатывается и не хранится — это упрощает всё остальное.
- **Согласие бабушки** — не только техническое, но и оформленное при настройке:
  экран «Что видит Петя и что он не видит», с явным подтверждением.
- Несовершеннолетние помощники: не запрещаем, но и не ориентируемся на них.

## 6. Что может убить релиз

| Риск | Смягчение |
|---|---|
| Отказ по stalkerware из-за формулировок в описании | вычитать описание и скриншоты по §1, убрать «контроль», «незаметно» |
| Отказ по `SYSTEM_ALERT_WINDOW` / `PACKAGE_USAGE_STATS` | заранее подготовленные обоснования + видео |
| Отказ по Accessibility (V2) | V1 без него; Device Owner как запасной путь |
| Верификация разработчика не пройдена вовремя | начать за 2–3 месяца до пилота |
| Data safety не совпадает с реальным поведением | сверять форму с кодом при каждом релизе — расхождение хуже, чем сам сбор |

## 7. Чек-лист перед подачей

- [ ] В описании и на скриншотах нет слов «скрытно», «незаметно», «контроль за».
- [ ] Первый абзац описания говорит о видимости и согласии.
- [ ] Видео сценария записано и приложено.
- [ ] Data safety сверена с реальным списком данных из [security.md](security.md) §5.
- [ ] Политика приватности опубликована и доступна по ссылке.
- [ ] Обоснования для overlay, usage stats, foreground service types готовы.
- [ ] Accessibility в V1 не объявлен и не используется (проверить по манифесту).
- [ ] Верификация разработчика пройдена.
